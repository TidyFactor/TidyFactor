# Why TidyFactor Exists

The web has changed.

Artificial Intelligence did not simply make software development faster.

It fundamentally changed how software is created, understood, maintained, and evolved.

The traditional web stack was designed for humans writing code.

The next generation of web platforms must be designed for collaboration between humans, AI models, autonomous agents, and future intelligent systems.

TidyFactor exists to build software for that new reality.

---

# Our Vision

We envision a future where websites and applications are no longer static collections of pages or tightly coupled codebases.

Instead, they become structured, modular, machine-readable systems that are equally understandable by:

* Humans
* Developers
* AI Models
* Autonomous Agents
* Future Tools

Modern software should not only render beautifully.

It should communicate intelligently.

---

# Our Mission

Build an open platform for creating modern websites and applications that are:

* Architecturally clean
* AI-native
* Content-driven
* Portable
* Maintainable
* Extensible
* Performant
* Framework-agnostic
* Future-ready

# The Problem

Today's web ecosystem suffers from unnecessary complexity.

Projects become increasingly difficult to understand.

Content is mixed with presentation.

Business logic becomes tightly coupled to frameworks.

Generated code becomes disposable instead of maintainable.

Even AI-generated projects often inherit yesterday's architecture.

The future deserves better.

---

# Our Philosophy

## Structure over Complexity

Software should become simpler as it grows.

Architecture should reduce complexity instead of creating it.

---

## Content over Code

Content should exist independently from presentation.

Knowledge should outlive frameworks.

---

## Data First

Information is the product.

Interfaces are merely one way to visualize it.

Everything should be representable as structured data.

---

## AI Native

Artificial Intelligence is not another feature.

It is now a first-class participant in the software lifecycle.

Every system should be designed to collaborate naturally with AI.

---

## Open by Design

Data should remain portable.

Projects should remain understandable.

Developers should never feel trapped.

---

## Convention over Configuration

Sensible defaults should eliminate unnecessary decisions.

Configuration should exist only when it provides real value.

---

## Evolution over Replacement

Technology constantly changes.

Good architecture should survive technological shifts.

TidyFactor is designed to evolve with the web instead of chasing trends.

---

# AI Native Principles

Modern software should treat AI as a native citizen rather than an external integration.

This means embracing formats and workflows that enable intelligent collaboration.

Examples include:

* Structured JSON
* Markdown
* Semantic metadata
* Portable schemas
* Machine-readable content
* AI-friendly exports
* AI-friendly imports
* Knowledge serialization
* Agent interoperability
* Context-aware workflows

Every piece of information should be portable.

Every project should remain understandable.

Every workflow should be automatable.

# Design Tenets

Every decision inside TidyFactor should move software toward these characteristics:

- Simple before clever.
- Explicit before implicit.
- Structured before generated.
- Portable before proprietary.
- Content before presentation.
- Standards before conventions.
- Small before bloated.
- AI-native before AI-powered.

---

# Non Goals

TidyFactor does not aim to become:

- A visual no-code builder.
- A low-code platform.
- A WordPress clone.
- A framework that replaces existing ecosystems.
- An enterprise platform overloaded with features.

Our goal is to build focused tools that solve real engineering problems without unnecessary complexity.

# The TidyFactor Test

Before adding any feature, ask:

Is it simpler?

Is it more maintainable?

Does it improve interoperability?

Does it reduce lock-in?

Is it AI-native?

Can it survive future technology changes?

Would we still choose this approach five years from now?

---

# Product Philosophy

Every product inside the ecosystem should answer one question:

"Does this reduce complexity while increasing capability?"

If the answer is no, it probably does not belong inside TidyFactor.
